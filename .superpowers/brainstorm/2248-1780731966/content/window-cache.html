WindowCache — 窗口枚举缓存层

合并现有 WindowManager，一次 EnumWindows，多处查询

核心数据结构

struct CachedWindowInfo {
    HWND   hwnd;
    QString title;
    DWORD  pid;
    QString exeName;       // basename（无 .exe）
    bool   isVisible;      // IsWindowVisible && !IsIconic
    bool   isMinimized;    // IsIconic
    bool   isForeground;   // GetForegroundWindow() == hwnd
    bool   isToolWindow;   // WS_EX_TOOLWINDOW
};

using WindowList = QList<CachedWindowInfo>;

QHash<QString, WindowList>  m_windowsByClass;   // wmClass → 窗口列表
QHash<DWORD, QString>        m_pidToExeName;     // PID → exe basename 缓存

查询接口（供 ClickStateMachine 使用）

方法 返回
hasVisibleWindows(wmClass) 是否有 IsWindowVisible && !IsIconic 窗口
hasMinimizedWindows(wmClass) 是否有 IsIconic 窗口
hasHiddenWindows(wmClass) 是否有不可见且非最小化的窗口（托盘隐藏）
isForegroundApp(wmClass) 前台窗口是否属于此应用
getWindowCount(wmClass) 可见窗口数量（保持兼容现有 API）
getForegroundHwnd(wmClass) 应用的前台窗口 HWND，若无则返回上次激活的
getLastActiveHwnd(wmClass) 最近激活过的窗口 HWND（用于恢复）

刷新策略

主动刷新：ProcessMonitor::onTick 每次调用后触发 WindowCache::refresh()
按需刷新：第一次查询或上次刷新超过 500ms 时自动 refresh
事件触发：DockWindow 收到 WM_ACTIVATE / WM_SETFOCUS 时强制刷新

Zm-order 追踪：refresh 时记录 GetForegroundWindow() 归属，保留上次激活窗口的 HWND。
应用切换时更新 lastActiveTime，S1→S2 恢复时优先恢复最近激活的窗口。

多进程匹配（解决 Chrome/VS Code 类应用）

1. 主匹配：execPath basename == 进程 exe basename（现有逻辑）
2. PID 反查：EnumWindows 获取窗口 PID → QueryFullProcessImageName → 与 wmClass 比较
3. 目录锚点：对于 Chrome，检查进程路径是否在同一个安装目录下
4. 已知映射表：硬编码常见多进程应用的子进程映射（如 "chrome" → "chrome" 所有变体）
